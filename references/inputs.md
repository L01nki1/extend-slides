# 输入处理

本文件定义支持哪些输入、如何解析、解析失败时如何降级。核心原则：**任何能力缺失都不阻断流程**，一律降级为「向用户给出具体导出指引」，并让用户知情。

---

## 支持的输入格式

| 输入类型 | 识别特征 | 解析方式 | 失败回退 |
| --- | --- | --- | --- |
| PPTX | `.pptx` | `scripts/extract_pptx.py` 抽取每页文字与备注 | 请用户导出 PDF |
| PPT（旧格式） | `.ppt` | 无法直接解析 | 请用户用 PowerPoint / LibreOffice 另存为 `.pptx` 或 PDF |
| 文本型 PDF | 可选中文字的 `.pdf` | 直接读取文本 | 若为乱码或空文本，按扫描件处理 |
| 扫描版 PDF | 选中无文字或为图片的 `.pdf` | `scripts/render_pdf_images.py` 逐页转图，再多模态直读 | 无 OCR 且无法直读 → **跳过该页** |
| 图片 / 截图 | `.png` `.jpg` `.jpeg` `.webp` | 多模态直读 | 无法辨识 → **跳过**，不要猜测 |
| 录音转写文本 | `.txt` `.md` `.srt` `.vtt` | 直接读取；或按以下规则处理| 请用户确认说话人分段，或补全缺失段落 | 录音转写错误较多时无法复原时，向用户说明**内容将会被跳过** |
| Word 讲义 | `.docx` | 直接读取；必要时先转 Markdown | 请用户另存为 PDF 或 Markdown |
| Markdown 讲义 | `.md` | 直接读取 | — |
| 教材 | 用户主动提供时才纳入 | 同 PDF 规则 | 若未提供，不要向用户索要教材 |

> **注意**：教材是可选输入。用户没有主动提供时，不要主动索取，也不要假设用户有教材。

## 能力探测

先运行 `scripts/probe_env.py` 得到本机能力清单：

```powershell
python scripts/probe_env.py
```

若脚本无法运行（无 Python），按下表人工确认，或直接走降级路径：

| 能力 | 探测方式 | 提供的能力 |
| --- | --- | --- |
| python-pptx | `python -c "import pptx"` | 直接抽取 PPTX 文字与图片 |
| LibreOffice | `soffice --version` | PPT / Word 转 PDF |
| poppler | `pdftoppm -v` | PDF 逐页转图片 |
| OCR | `tesseract --version` | 扫描件文字识别（仅在多模态直读不可靠时使用） |

探测结果**必须在流程开始时主动告知用户**（其中 OCR 必须单独说明），不能只在交付报告里追溯；交付报告里再补充：哪些走了脚本、哪些走了人工导出。

## 降级与导出指引

缺失能力时，向用户给出**可直接照做的**指引，不要只说「请提供 PDF」。

- **无 python-pptx**：让用户在 PowerPoint 中「文件 → 导出 → 创建 PDF」，或「另存为 → PDF」；若只需部分页面，直接截图即可。
- **无 LibreOffice**：同上，用 PowerPoint 手动导出。
- **无 poppler**：让用户用 PDF 阅读器「打印 → 另存为 PDF」不可行时，改用截图；或逐页截图保存为图片。
- **无 OCR**：**必须主动告知用户，不要静默降级。** 说明纯图片素材会先尝试多模态直读、无法可靠识别的页面将被跳过，并按需贴出安装指令：
  - `winget install --id UB-Mannheim.TesseractOCR --exact --accept-package-agreements --accept-source-agreements`（需管理员权限，会弹 UAC）
  - 已装 Chocolatey 的可用：`choco install tesseract -y`（同样需要管理员终端）
  - 安装向导中需勾选 **Chinese (Simplified)** 语言包，否则中文识别会失败；装完需**重启 VS Code** 才能让新 PATH 生效
  - 用户选择不装时直接继续：纯图片页（无可提取文字）跳过，不要把这些页面的图片贴进 Markdown 顶替正文；跳过项逐条记入交付报告的存疑条目。图片过于模糊导致无法辨识时，如实标注 `无法辨识`，不要猜测。

## 输入处理的硬性规则

1. **默认不落地图片**：纯图片页在无 OCR 时直接跳过，**不要把图片贴进 Markdown 顶替正文**；也不要以「保留原貌」为由批量粘贴课件截图 —— 产物是可读的讲解文档，不是图片集。
2. **只在必要时落地图片**：当该页含可提取文字、或本机有 OCR、且图片确实承担解释作用时，才把图片写入 `<课程输出目录>/assets/`，文件名用 `<编号>-<页码>-<用途>.<扩展名>`，例如 `03-12-backprop-graph.png`。
3. **图片必须有说明**：每张保留下来的图都要配「它解释什么、看图顺序、能得出什么结论」三要素。只插图不解释视为不合格。
4. **跳过的内容不得静默丢弃**：跳过的纯图片页、无法提取的图片，都要逐条记入交付报告的「存疑条目」。若该页有文字但图片提取失败，用文字占位 `[图片无法提取：<文件名> 第 N 页]`。
5. **PDF 文本乱码要判断原因**：先确认是否为扫描件；若为字体嵌入问题，按扫描件走图片路径，不要硬猜乱码内容。
6. **转写文本要容忍噪声**：口语重复、语气词、识别错误不要直接搬进正文；需要提炼成书面表述。若某段语义不明，标注 `[转写不清晰：<时间点>]` 而不是编造。
7. **多份材料冲突时**：以授课材料（课件 / 讲义）为准，转写文本作补充；冲突处如实并列，不要自行裁决。
8. **同一页有多种版本时**（如 PPT 源文件 + OCR + 截图）：优先使用源文件；源文件不可用时，OCR 提供文字线索，截图提供版式、层级、箭头、分组与图表关系。**禁止只读 OCR 就断言空间关系。**
9. **录音转写文本的特殊处理**：
   - **先修正错误**：录音转写可能存在语音识别错误、标点缺失、重复啰嗦、口语化表述等问题，必须先进行校正，将口语表述转化为书面化、准确的知识表述。
   - **选取重点**：转写内容通常比课件长，需要从其中提取**教学重点、关键例题、重要推导**，将课堂讲解的精华部分作为讲解主体。
   - **补充不足**：AI 讲解需识别老师讲解的**不足之处、未展开的细节、未补充的背景**，用 `==...==` 标记补充内容，确保不遗漏知识点。
   - **课堂内容置顶**：如果转写内容与课件内容存在对应关系，应将转写内容放在课件内容的**较高位置**，作为对课件的补充讲解。
   - **题目处理**：若转写中包含题目，可以在此基础上稍作修改，作为课后题的一部分，但需确保题目的完整性和正确性。
10. **术语翻译的通用性**：中英文术语对照表中，中文术语应采用**最通用、最规范的表述**，避免生僻或过时的翻译，确保学习者能找到一致的标准表达。
